#### DEC-026 — 9.6 실험: GitHub Copilot Agent Mode 단독 완결성 검증
- **상태:** 확정
- **일자:** 2026-09-27
- **배경:** 하나테니스클럽 프로젝트에서 쌓은 "AI 작업을 사람이 승인·검증하며
  통제하는 체계"를 유지하면서도, 사람이 Copilot 채팅과 VS Code 터미널
  사이를 매번 수동으로 복사·실행·보고하는 병목을 줄일 수 있는지 검증하기
  위해, kcoc-weekly Phase 2(콘텐츠 수집기 최초 구현)를 대상으로 GitHub
  Copilot Agent Mode 단독 실행 실험을 진행했다.
- **실험 조건:**
  - 대상 작업: 정책 문서(SOURCE_POLICY/STATE_POLICY/CONTENT_POLICY) 기준
    가상 기사 3건을 다루는 목업 수집기(`collect-mock.mjs`)와 단위 테스트
    작성
  - 격리: `experiment/agent-mode-phase2` 브랜치에서만 진행, main 미접촉
  - 모델/설정: Auto, Balance
  - 성공 기준: "설계 → 구현 → 검증 → 커밋"을 사람 개입 없이 한 세션에서
    완결하는가
- **결과:**
  - 총 30 steps, 2분 6초(Agent 자체 측정) 만에 세션 완료
  - 사람 개입 **1회** — SOURCE_POLICY.md에 JSON 필드명·타입이 정의되어
    있지 않아, Agent가 임의로 정하지 않고 스키마 확정을 질문함
  - 설계 단계: 완료(정책 문서 8개 검토 후 계획 수립)
  - 구현 단계: 완료(`collect-mock.mjs`, `collect-mock.test.mjs` 생성)
  - 검증 단계: 부분 완료 — `check-static`/`check-content`/`check-links`
    통과, 통합 검사(`check-naming` 포함 `check-all`)만 실패
  - 커밋 단계: **보류** — 실패 원인이 Agent의 작업물이 아니라, 사전에
    사람이 프로젝트 루트에 남겨둔 미추적 로컬 도구
    (`audit-kcoc-weekly.ps1`, 74행에 구 저장소명 검색 패턴 포함)를
    `check-naming.mjs`가 감지한 것으로 확인되자, Agent는 이 파일을
    임의로 수정·삭제하지 않고 저장소 Gate가 완전히 통과하지 않았다는
    이유로 커밋을 스스로 보류함
  - **최종 판정: 4단계 완결 여부 = N (사람 개입 1회, 커밋 미완료)**
- **부수적으로 확인된 사항:**
  - 자신이 만들지 않은 파일의 오류를 임의로 은폐하거나 삭제하지 않는
    책임 경계 판단이 실제로 작동함
  - 단위 테스트가 구현 코드의 상수를 그대로 참조해 항상 통과하는 구조적
    함정을 스스로 발견, 정책 문서 기준값으로 테스트를 독립시켜 재검증함
    (지시하지 않은 자발적 품질 개선)
  - 실행 중 응답 일부가 일시적으로 러시아어로 출력되는 현상이 1회
    있었으나 내용의 정확성 자체에는 문제가 없었음(원인 미상, 재발
    여부 추적 필요)
  - 검증 스크립트 실행 시 cwd를 프로젝트 루트로 정확히 유지하는 등,
    사람이 과거에 겪었던 실수(cwd 오류로 인한 MODULE_NOT_FOUND)를
    Agent는 재현하지 않음
- **판단:**
  1. 이번 결과의 미완결 원인은 Agent Mode 자체의 한계가 아니라 **실험
     설계상의 오염**(로컬 감사 도구를 프로젝트 루트에 남겨둔 것)이었다.
     오염 요인을 제거하면 "개입 0회·커밋까지 완결" 가능성이 높다고
     판단한다.
  2. 다만 개입 1회(정책 공백 시 임의 결정 대신 질문)는 실패가 아니라
     **의도된 안전장치가 정상 작동한 사례**로 평가한다. "개입 횟수
     0"만을 성공 기준으로 삼는 것은 과도하게 엄격할 수 있으며, "정책이
     명확한 범위에서는 자율 완결, 불명확하면 반드시 질문"이 오히려
     바람직한 기준으로 재정의한다.
- **후속 조치:**
  - `audit-kcoc-weekly.ps1`류의 일회성 로컬 도구는 프로젝트 루트가 아닌
    별도 위치(예: `C:\Tools\`)에 두거나 `.gitignore` 등록을 표준 관행화
    한다.
  - 오염 요인 제거 후 동일 실험을 1회 재실행하여 "완전한 4단계 완결"
    재현 여부를 추가 검증할지는 별도 결정 사항으로 둔다(본 DEC에서는
    확정하지 않음).
  - 향후 Agent Mode를 하나테니스 프로젝트에도 적용할지는 이번 kcoc-weekly
    결과(9.5/9.6 트랙 누적 데이터)를 근거로 별도 판단한다.

#### DEC-027 — PowerShell 실행 정책 오류 재발 방지 규칙 확정
- **상태:** 확정
- **일자:** 2026-09-27
- **배경:** Copilot이 생성해 다운로드로 전달한 `source-feasibility-check.ps1`
  실행 시 "파일이 디지털 서명되지 않았습니다" 오류(PSSecurityException,
  UnauthorizedAccess)가 발생했다. 원인은 스크립트 내용의 결함이 아니라,
  Copilot이 생성하는 모든 `.ps1`이 서명되지 않은 채 다운로드 경로를 거쳐
  전달되기 때문에 Windows 기본 실행 정책에서 구조적으로 항상 발생하는
  문제였다.
- **결정:**
  1. Copilot이 새 `.ps1` 실행을 안내할 때는 실행 명령 직전에
     `Set-ExecutionPolicy -Scope Process Bypass`를 예외 없이 포함한다.
     이를 누락하는 것은 실패 패턴으로 취급한다.
  2. 사용자가 원한다면 `-Scope CurrentUser`로 1회 영구 설정하는 대안도
     제공하되, 이는 회사 보안 정책 확인 후 사용자가 직접 판단해 실행한다.
  3. 조직 GPO로 실행 정책 자체가 강제된 경우를 대비한 우회 경로(로컬
     직접 저장 방식)도 함께 문서화한다.
- **적용 범위:** 이 규칙은 kcoc-weekly뿐 아니라 하나테니스클럽을 포함한
  모든 프로젝트에서 Copilot이 `.ps1`을 전달할 때 공통 적용한다.
- **문서 반영:** kcoc-weekly `docs/WORKSPACE.md` §10에 추가.

##### DEC-028 - 외부 AI API 파이프라인의 단계별 복원력 검증 원칙
- **상태:** 확정
- **일자:** 2026-09-28
- **배경:** Gemini 번역 파이프라인에서 종료된 모델, 모델 ID와 리소스 경로 혼동, HTTP 503, 비구조화 응답이 연속적으로 발생했다. 디버깅 과정에서도 PowerShell 형식명 오타, 비종료 오류 이후 거짓 성공 메시지, UTF-8 BOM 추가와 한글 인코딩 손상이 발생해 문제 범위가 확대되었다.
- **결정:**
  1. 외부 AI API 작업은 파일 문법과 인코딩, 환경변수, 모델 ID와 엔드포인트, 최소 요청 1건, 실제 데이터 1건, 전체 배치, 프로젝트 Gate 순서로 검증한다.
  2. 단일 실제 데이터 검증 성공 전에는 전체 배치를 실행하지 않는다.
  3. 408, 429, 5xx와 네트워크 오류만 제한적으로 재시도한다.
  4. 재시도에는 지수 백오프, 지터, 최대 횟수를 적용하고 `Retry-After`가 있으면 우선한다.
  5. 400, 401, 403, 404는 자동 반복하지 않는다.
  6. JSON이 필요한 작업은 프롬프트 지시에만 의존하지 않고 구조화 출력을 사용한다.
  7. 성공 항목만 저장하고 실패 항목은 재처리 가능한 상태로 유지한다.
- **작업 안전 규칙:**
  1. 동일한 수정 계층에서 2회 연속 실패하면 작업을 중단한다.
  2. 손상 파일을 계속 부분 수정하지 않고 정상 백업 또는 Git 기준본으로 복원한다.
  3. 파일 형식별 인코딩 정책을 구분한다.
  4. 실제 사후 검증 전에는 `[OK]`, `[PASS]`, 완료 메시지를 출력하지 않는다.
  5. 설명과 최종 명령의 문자 단위 일치 여부를 검토한다.
- **후속 조치:** 다음 세션에서 503 재시도와 JSON 구조화 출력 FIX SPEC을 한 번에 구현한다. 문법 및 인코딩 검사 후 단일 기사에 성공한 경우에만 6건 전체 실행으로 진행한다.
- **관련 문서:** `AI_WORKING_RULES.md`, `WORKSPACE.md`, `CURRENT_STATE.md`, `CHANGELOG.md`


##### DEC-029 - Gemini 번역 파이프라인 복원력 FIX SPEC 구현 및 모델 폴백 도입
- 상태: 확정
- 일자: 2026-09-29
- 배경: DEC-028에서 정의한 재시도·구조화 출력 FIX SPEC을 실제로 구현했다.
  실사용 검증 중 gemini-3.8-flash가 HTTP 503(UNAVAILABLE, Google 서버 측
  일시적 고부하)과 HTTP 429(무료 티어 일일 한도 20 RPD 소진)를 함께
  반환하는 것을 확인했다. 1차로 시도한 폴백 모델 gemini-2.5-flash는
  Google이 2026-09-18부로 신규 프로젝트 접근을 제한해(HTTP 404 "no
  longer available to new users") 즉시 실패했다.
- 결정:
  - 408/429/5xx/네트워크 오류에 한정해 모델당 최대 4회 지수 백오프+지터
    재시도를 적용하고, Retry-After 헤더를 우선한다(DEC-028 유지).
  - Gemini 요청에 responseMimeType과 responseSchema를 추가해 JSON
    구조화 출력을 강제하고, HTTP 성공 후 형식 오류는 최대 1회만
    재시도한다(DEC-028 유지).
  - 기본 모델(gemini-3.8-flash)에서 재시도 한도를 모두 소진해도
    재시도 가능한 오류가 계속되면 gemini-3.5-flash-lite로 자동 전환한다.
    이 모델은 Google이 신규 프로젝트에 공식 권장하며, 무료 티어 일일
    한도가 500 RPD로 gemini-3.8-flash(20 RPD)보다 훨씬 넉넉하다.
  - 400/401/403/404 등 재시도 불가능한 오류는 모델 전환 없이 즉시
    실패로 전파한다(설정 문제이므로 폴백해도 동일하게 재현됨).
  - 폴백 모델 목록은 GEMINI_FALLBACK_MODELS 환경변수로 재정의 가능하며,
    기본값은 gemini-3.5-flash-lite 단일 모델이다.
- 검증:
  - mock 기반 로직 테스트: 503 회복, 형식오류 1회 재시도, 404 즉시실패,
    재시도 한도 초과 실패, Retry-After 우선, 네트워크 오류 회복, 혼합
    배치에서 성공만 저장·실패는 재처리 가능 상태 유지, 재실행 멱등성,
    모델 폴백 전환(503/429 소진 후 폴백 성공, 404는 폴백 없이 즉시실패)
    을 모두 통과했다.
  - 실사용 검증: 2026-W40 이슈 대상으로 단일 기사 검증 성공(폴백 모델
    gemini-3.5-flash-lite로 정상 번역), 이어서 6건 전체 실행 성공
    (번역 6건, 실패 0건)을 확인했다.
- 후속 조치:
  - scripts/translate-summarize.mjs 안에 남아있던 일회성 검증 파일
    scripts/translate-summarize.restore-test.mjs(구 /models/models/
    중복 엔드포인트 버그가 재현된 미추적 잔재 파일)를 삭제했다. 이
    파일은 Git에 커밋된 적이 없고 다른 코드에서 참조되지도 않아 실제
    실행에는 영향이 없었음을 확인했다(WORKSPACE.md §12 사례와 동일).
  - node scripts\check-all.mjs 통과 및 git diff 검토 후 커밋 진행.
  - gemini-3.8-flash의 무료 티어 일일 한도(20 RPD)가 낮으므로, 향후
    발행 규모가 커지면 유료 티어 전환 또는 gemini-3.5-flash-lite를
    기본 모델로 승격하는 방안을 별도로 검토한다(본 DEC에서는 확정하지
    않음).
- 관련 문서: AI_WORKING_RULES.md, WORKSPACE.md §15, CURRENT_STATE.md §6,
  CHANGELOG.md, DEC-028
